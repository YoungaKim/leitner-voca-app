# 라이트너 영어 암기장 앱 — UX/UI 설계 문서

> 관련 문서: 기획 → `01-PRD.md` · 설계 → `02-DESIGN.md` · 플로우 → `leitner-vocab-app-flow.html`
> 플랫폼: Android / Jetpack Compose + Material 3 · PC 웹 / React
> 공통 pool·서버 저장 상태 반영: 2026-10-08. 화면별 미구현 기능 제안은 기존 계획으로 유지한다.
> 대상: 토익·토플 시험 대비 학습자

## 0-1. 플랫폼 확장 원칙 (PC 웹)

이 문서는 **Android(Compose) 화면 설계를 기본**으로 하며, 공통 데이터 표시·저장 실패 동작과 PC 웹 전용 기능은 함께 명시한다. PC 웹(Windows/macOS 브라우저)은 아래 원칙만 정해두고, 화면별 상세 스펙(레이아웃·컴포넌트·마이크로카피)은 웹 UI를 실제로 만들 때 그때그때 정한다.

- **공유되는 것**: 라이트너 스케줄러 로직, 데이터 모델, 알고리즘·채점 규칙(§DESIGN §1), Supabase 동기화 계층. 플랫폼 무관하게 동일해야 함.
- **플랫폼별로 따로 그리는 것**: 실제 UI 컴포넌트·레이아웃. Compose 스펙(NavigationBar, dp 단위, Material 3 등)을 웹에 그대로 이식하지 않는다 — 웹은 웹 컴포넌트 체계(예: 반응형 그리드, CSS 기반 디자인 토큰)로 별도 설계.
- **동등하게 유지해야 하는 것(기능 패리티)**: 학습 세션의 3단계 흐름(제시→힌트→정답 확인), 힌트 사다리·채점 규칙, 박스 색상 스케일 의미, 핵심 마이크로카피 톤. 즉 "다르게 그리되 같은 규칙으로 동작"해야 한다.
- **PC 특화 여지**: DESIGN §4.1에 따라 PC는 장시간 학습·카드 편집·통계 확인이 중심 사용처이므로, 모바일보다 더 넓은 레이아웃(예: 카드 목록+상세 동시 표시, 키보드 단축키)을 웹 화면 설계 시점에 검토한다.

## 0-2. PC 키보드 접근성 요구사항

PC 웹은 마우스 없이 **키보드만으로 모든 버튼을 조작 가능**해야 한다(모바일에는 해당 없음).

- **전역 원칙**: 화면에 노출된 모든 버튼·토글·입력은 `Tab`/`Shift+Tab`으로 포커스 이동이 가능해야 하고, 포커스 상태가 시각적으로(아웃라인 등) 명확히 보여야 한다. 포커스된 버튼은 `Enter` 또는 `Space`로 활성화(브라우저 기본 동작). 단, §3.3 학습 세션의 "정답 확인" 전역 단축키는 `Enter`만 쓴다(위 참고).
- **학습 세션(§3.3) 전용 단축키** — 손을 키보드에서 떼지 않고 학습이 끝까지 진행되게 하는 것이 목적:
  | 키 | 동작 | 비고 |
  |---|---|---|
  | `H` | `[힌트]` 클릭과 동일(레벨 1씩 공개) | 마우스 이동 없이 반복 호출 가능해야 함 |
  | `Enter` | 제시 상태에서 `[정답 확인]` 실행 | Space는 쓰지 않음 — 텍스트 정답 입력창에 포커스를 안 준 채 답을 구상하며 스페이스를 누르는 습관 때문에 의도치 않게 정답이 열릴 수 있어서 제외(§3.3 텍스트 정답 입력 추가로 결정 변경) |
  | `Tab` → `Enter`(또는 `Space`) | `[몰랐어]`/`[알았어]` 중 포커스된 쪽 선택 | 정답 확인 후에는 기본 포커스가 `[알았어]`에 오도록 하되, 힌트 레벨 2+로 비활성화된 경우 `[몰랐어]`에 옴 |
  | `←` `→` (선택) | `[몰랐어]`/`[알았어]` 사이 포커스 이동 | Tab 이동과 동등한 보조 수단, 필수는 아님 |
  | `Esc` | 좌측 `[X]` 나가기와 동일(진행 저장 후 종료) | |
  - 단축키는 학습 화면이 포커스를 가진 동안에만 동작(다른 화면·모달 열림 상태에서는 비활성).
  - `H`/`Enter` 단축키 존재는 최초 학습 세션 진입 시 짧은 툴팁/힌트 텍스트로 1회 안내(예: "H = 힌트, Enter = 정답 확인").
- **접근성 예외**: 텍스트 입력 필드(카드 추가·편집 폼, 검색창, §3.3의 텍스트 정답 입력창, 선생님 질문 입력창 등)에 포커스가 있을 때는 `H` 등을 단축키로 가로채지 않고 원래 입력 동작을 우선한다. 입력창 안에서 `Enter`는 이 전역 단축키가 아니라 §3.3의 텍스트 정답 제출로 동작한다.
- **범위**: 이 요구사항은 §3.3 학습 세션에 우선 적용하고, 이후 단어장/설정 등 다른 P0 화면에도 동일 원칙(Tab 이동·Enter 활성화)을 확장 적용한다.

## 0. 디자인 원칙

책의 두 축("놀이처럼 · 부담 제거" + 시험 대비 효율)을 화면으로 옮긴다.

1. **저마찰(low friction)** — 앱 열고 [학습 시작]까지 1탭. 학습 화면엔 방해 요소 0.
2. **상자 메타포** — 라이트너의 물리적 카드 상자를 시각적 정체성으로. 박스 1~6을 실제 칸처럼 그린다.
3. **극단적 단순함(학습 화면)** — 카드 + 버튼 2개. 그 외 아무것도 없음.
4. **동기 부여 상시 노출** — 연속 학습일, D-day, 박스 승급 피드백으로 성취감 제공.
5. **정보를 색+숫자 이중 표기** — 색맹 고려, 박스는 색상과 번호를 함께 표기.

---

## 1. 디자인 시스템 / 토큰

**컬러**
- Material 3 다이나믹 컬러 기반, 다크모드 필수 지원.
- **박스 단계 색상 스케일**(진척 시각화의 핵심):
  | 박스 | 색 계열 | 의미 |
  |---|---|---|
  | 1 | 레드 | 취약/신규 |
  | 2 | 오렌지 | 익숙해지는 중 |
  | 3 | 옐로 | 꽤 앎 |
  | 4 | 라임 | 거의 외움 |
  | 5 | 그린 | 장기기억 |
  | 6 | 틸/블루그린 | 안정화 |
  | 졸업 | 골드 | 마스터 |
  > 색만으로 구분하지 않도록 항상 박스 번호를 병기.

**타이포**
- Material 3 typography scale 사용.
- **학습 단위 = 문장.** 카드는 2~3줄이 되므로 학습 화면 문장은 `titleLarge`~`headlineSmall`(18~22sp) + 행간 1.6, **왼쪽 정렬**. 단어처럼 초대형 중앙정렬은 쓰지 않는다.
- 정답 문장에서 **핵심 청크(구문)는 색/굵기로 강조**해 시선을 잡아준다.

**형태/모션**
- 카드 = 물리적 느낌: 라운드 코너 16dp, 은은한 elevation.
- 카드 뒤집기: Y축 3D 플립 애니메이션(200~300ms).
- 정답 시 카드가 해당 박스로 "날아가는" 마이크로 모션.

**접근성**
- 터치 타깃 최소 48dp, [알았어]/[몰랐어]는 화면 하단에 크게(엄지 도달 영역).

**하단 탭 바(NavigationBar) 4개:**
`홈` · `단어장` · `통계` · `설정`

- **학습 세션은 탭이 아님** — 홈에서 [학습 시작]으로 진입하는 전체화면 플로우.

## 3. 화면별 설계

### 3.1 온보딩 (첫 실행)

3스텝, 전부 스킵 가능. 목적은 "즉시 학습 시작"까지 최단 경로.

1. **한 줄 소개** — "아는 단어는 뜸하게, 모르는 단어는 자주. 라이트너 상자 학습법."
2. **목적 선택** — 토익 / 토플 / 둘 다 (칩 선택)
3. **D-day 입력(선택)** + **스타터 덱 추가 제안** — [스타터 단어장 담기] / [건너뛰기]

→ 완료 시 홈으로. 온보딩은 재실행 안 함(설정에서 다시 보기 가능).

---

### 3.2 홈 / 상자 대시보드 ★메인

앱의 얼굴. 열자마자 "오늘 뭘 할지"가 1초 안에 보여야 함.

**레이아웃(위→아래):**
- **상단 바** — 인사말 + 우측에 `D-14` 배지, `🔥 연속 7일` 스트릭.
- **카드 상자 시각화** — 신규(박스0)·박스1~6·졸업을 왼쪽부터 배치한 계단형 차트. 칸 높이는 단계별로 커지고, 색은 칸 바닥부터 채운다. PC/모바일 홈 목업은 `screen-home-pc.html`·`screen-home-mobile.html` 참고.
  - 각 칸 위에 카드 수, 칸 안에 상대 비율, 하단에 `신규 / 1 / … / 6 / 졸업` 라벨을 표시한다.
  - **채움·비율 기준 = 가장 카드가 많은 칸을 100%**. 두 표시가 같은 기준을 사용한다. 빈 칸은 점선 테두리로 유지한다.
  - 총 문장 수·취약(박스1~2)/졸업 비율은 전체 학습 카드 수 기준이다. 막대의 상대 비율과 구분한다.
  - 차트는 현황 표시다. 칸 클릭/롱프레스 목록 이동은 기존 설계 제안이며 현재 구현 완료로 간주하지 않는다. `leitner-physical-box.html`은 초기 물리적 상자 메타포 참고 자료다.
- **오늘 목표(핵심 CTA)** — `오늘 목표 N개 · 완료 M개`, 진행 바, 남은 큐 내역, 오늘 박스 이동 집계, [학습 시작].
  - `N = 남은 due 복습 + 박스0 잔류 + 도입 가능한 pool 신규 + M`. `M`은 마지막 채점 날짜가 오늘인 카드 수다.
  - `dailyGoal` 설정 값은 신규 유입 조절값이며, 화면의 `오늘 목표`를 그 숫자로 고정하지 않는다. 밀린 복습은 모두 포함한다.
  - `남은 신규 A · 박스1 B · …`는 남은 큐의 구성으로, 합계는 `N-M`이다. 신규에는 미채점 박스0와 이번에 도입할 pool 문장을 포함한다.
  - `신규 K개 · 승급 U개 · 강등 D개 · 유지 F개`는 오늘 학습 로그의 이벤트 집계다. 같은 카드를 반복 채점한 경우 완료 카드 수와 로그 합계는 다를 수 있다.
  - 기기별 고정 목표 스냅샷을 저장하지 않는다. 공통 데이터·설정이 바뀌면 목표도 재계산된다.
- **하단 요약** — 총 카드 / 마스터. 상자 분포는 학습 카드 기준이며 미도입 pool은 별도 대기 재고다.

**상태(state):**

- *로그인 전*: Google 로그인 화면. localhost 로그인은 localhost로, 배포 웹 로그인은 해당 배포 origin으로 복귀한다.
- *웹 최초 서버 읽기*: 로딩 표시. 실패하면 오류와 [다시 시도]를 표시하며 캐시 숫자를 최신 서버 값처럼 확정하지 않는다.
- *카드 없음(빈 상태)*: 서버 읽기 성공 후 덱·카드가 없을 때 단어장 관리 안내.
- *오늘 학습 있음*: 위 기본 레이아웃. [학습 시작]을 누르면 최신 서버 상태를 읽고 성공 후 진입한다. 대기 중 중복 클릭을 막고 웹은 `동기화 중...`으로 표시한다.
- *저장/읽기 실패*: 오류 표시. 기존 데이터를 빈 화면으로 바꾸거나 저장된 것으로 표시하지 않는다.
- *오늘 큐 완료*: 목표 달성·오늘 완료/이동 집계 표시. 웹에 채점 미반영 다시보기 목록이 남으면 [다시 보기] 제공. 이 목록은 현재 브라우저 origin에만 저장되며 다른 기기까지 공유되는 완료 상태로 해석하지 않는다.

> 같은 계정·날짜·최신 서버 데이터에서 pool/박스/목표/완료/학습 기록 집계가 같아야 한다. 이미 열린 다른 화면은 DESIGN §3.9의 다음 pull 때 갱신된다. 실시간 공동 세션이나 화면 위치 공유는 제공하지 않는다.

### 3.3 학습 세션 ★핵심 인터랙션

전체화면. 하단 탭 숨김. 딴 데 신경 못 쓰게.

**학습 방식: 한글 → 영어 문장 생산(production).**
앞면에 한글 문장을 제시하고, 학습자가 **영어 문장을 스스로 떠올려 만든 뒤** 정답을 확인한다. 시험장에서 문장을 실제로 뱉는 능력을 기르는 게 목표.

> **신규 카드(박스0)** 는 복습 기한 없이 큐에 포함되고, 화면·힌트·채점 흐름은 아래와 완전히 동일하다. 채점 결과([몰랐어]/[알았어] 무엇을 눌러도)와 무관하게 채점 후 박스1로 진입해 정식 라이트너 사이클을 시작한다(DESIGN §1.3b).

**상단:**
- 진행 바 + `12 / 35`
- 좌측 [X] 나가기(진행 저장 후 종료) · 우측 현재 카드 박스 뱃지(예: `박스 3`).
- **내 상자 미니 스트립** — 진행 바 아래에 §3.2의 실물 상자 시각화를 축소한 버전을 상시 노출. 지금 푸는 카드의 박스 칸에 강조 테두리를 둘러
  "전체 상자 대비 이 카드가 어디 있는지"를 보여주고, 정답 확인 시 "[알았어]를 누르면 박스 N→N+1로 이동"처럼 다음 이동을 예고해
  학습 도중에도 상자가 채워지는 성취감이 끊기지 않게 한다.
- **`[🧑‍🏫 선생님한테 질문]` 아이콘 버튼(PC 웹)** — 상단 바의 [X] 나가기 옆에 배치. 클릭하면 카드를 가리지 않는 인라인 패널(모달 아님)이 열리고,
  자유 텍스트 질문 입력 + `[질문하기]` + 답변 표시 영역이 나타난다. 현재 카드의 한글 문장·영어 정답·청크 메모가 자동으로 컨텍스트에 포함되므로
  사용자는 질문만 입력하면 된다. 답변은 Claude/Gemini/GPT(설정 §3.6에서 선택한 모델) 중 하나로 생성되며, 질문-답변은 **1회성**(대화 히스토리 없음) —
  패널을 닫으면 사라진다. 로딩 중/에러(네트워크 실패, 서버 키 미설정) 상태를 패널 안에서 표시하고, 학습 흐름(제시→힌트→정답 확인)은 막지 않는다.
  (DESIGN §6)

**화면 상태 3단계:**

1. **제시(한글)** — 한글 문장 제시 + `[힌트]` + `[정답 확인]` + **(선택) 텍스트로 답 입력** 필드.
   > 예: "스마트폰은 어디에나 있다."
   > **텍스트 입력(PC 웹, 자기채점과 병행)** — 한글 문장 아래에 영어 답을 직접 타이핑할 수 있는 입력창을 상시 노출한다(제시 단계부터 힌트 단계까지 계속 입력 가능). `[제출]` 또는 Enter로 제출하면 §DESIGN §1.3a `matchesAnswer` 규칙(관사·대소문자·구두점 차이는 무시)으로 자동 비교한 뒤 곧바로 3. 정답 확인 상태로 넘어간다. 입력 없이 `[정답 확인]`을 눌러 기존처럼 진행하는 것도 그대로 가능 — 두 방식은 서로 배타적이지 않다.
2. **힌트(선택)** — `[힌트]`를 누를 때마다 아래 사다리로 영문 뼈대를 단계적으로 공개. 현재 레벨과 채점 영향 상태를 항상 표시.
3. **정답 확인** — 전체 영문 + 핵심 청크 강조 + **발음 자동재생** + 자기 채점 버튼.
   > **발음 자동재생 조건** — 설정에서 켜져 있으면 모든 카드에서 재생. 꺼져 있어도 **신규(박스0) 카드는 항상 자동재생**된다 — 처음 보는 문장이라 발음을 바로 들려주는 게 도움이 되기 때문(DESIGN §1.3b).
   > 앞면에 한글이 이미 있으므로 뒷면 여백엔 **끊어읽기 청크 / 문법 포인트**를 노출.
   > **텍스트 입력으로 진입한 경우** — `matchesAnswer` 일치 여부에 따라 `[몰랐어]`/`[알았어]` 중 해당 버튼이 미리 선택(강조) 표시되지만, 최종 채점은 사용자가 버튼을 눌러 확정한다(자동 제출 없음). **불일치(오답)** 시에는 정답 문장 위에 **단어 단위 diff**(입력한 단어 vs 정답 단어, 다른 부분 강조)를 보여주고, 카드에 `chunkNote`가 있으면 함께 노출해 왜 틀렸는지 설명한다. 이 diff는 규칙 기반으로 즉시 계산되며 별도 API 호출이 없다(DESIGN §1.3a).

**힌트 사다리 (KR→EN 생산):**

| 레벨 | 공개 내용 | 예시 | 채점 |
|---|---|---|---|
| 0 | 한글만 | `스마트폰은 어디에나 있다.` | — |
| 1 | 단어 수 + 첫 단어 | `Smartphones _ _.` (3단어) | **무료 (영향 없음)** |
| 2 | 모든 단어 첫 글자 | `S______ a__ u_________.` | **자동 오답(fail)** |
| 3 | 대부분 공개, 빈칸 1~2개 | `Smartphones are u_______.` | **자동 오답(fail)** |

> 레벨 개수·공개 범위는 상수(`hintLevels`)로 분리해 조정 가능.

**하단 — 버튼 & 채점 규칙:**
- *제시 상태*: `[힌트]`(고스트) · `[정답 확인]`(프라이머리).
- *정답 확인 후*:
  - **힌트 레벨 0~1 사용** → `[몰랐어]`(레드) · `[알았어]`(그린) 자기 채점.
  - **힌트 레벨 2 이상 사용** → `[알았어]` **비활성화**(또는 자동 `몰랐어` 처리). 규칙을 화면이 직접 집행해 "그래도 맞았다" 우회를 차단.
- 레벨 2로 넘어가기 직전 경고: `여기서부턴 다시 볼 카드로 분류돼요`.
- (선택) 좌=몰랐어 / 우=알았어 스와이프 제스처.
- **(PC 웹) 키보드 단축키**: `H`=힌트, `Enter`=정답 확인, `Tab`+`Enter`=몰랐어/알았어 선택. 상세는 §0-2 참고.

**저장 대기·실패(2026-10-08):**

- 채점 버튼은 서버 저장이 완료될 때까지 중복 입력을 막는다. 카드 진행과 학습 로그 저장 성공 후에만 다음 문장으로 이동한다.
- 실패하면 현재 문장과 오류를 유지한다. 오래된 카드 버전 충돌은 홈으로 돌아가 최신 상태를 읽고 다시 시작할 수 있게 한다.
- pool 신규 도입 실패 시 무한 로딩 대신 오류와 홈 복귀 경로를 제공한다. 이미 다른 기기에서 도입한 문장은 서버의 현재 카드를 사용한다.
- 미저장 채점은 종료 시 자동 저장/백그라운드 업로드되지 않는다. [X]는 이미 서버에 확정된 채점을 유지한 채 종료한다.

**피드백:**
- [알았어] → "박스 3 → 4 ↑" 짧은 토스트/모션, 카드가 다음 박스로 슥.
- [몰랐어] (또는 힌트 2+ 자동 오답) → "박스 1로" + 세션 끝 재노출 큐에 추가(02-DESIGN §1.5, box/주기엔 미반영).

> **알고리즘 연동(02-DESIGN §1.3):** `onAnswer`의 `correct` 판정 = (힌트레벨 ≤ 1) AND (사용자가 [알았어] 선택). 힌트레벨 ≥ 2 이면 `correct=false` 강제.

**세션 요약 화면(종료 시):**
- 오늘 학습 수 · 정답률 · 박스 이동 요약(↑n개, ↓m개, 신규 k개).
- 스트릭 갱신 애니메이션.
- 격려 메시지 + [홈으로] / [계속 학습](남은 큐 있으면).

### 3.4 단어장 / 카드 관리

**단어장 목록:**
- 덱 카드마다: 이름 · 총 카드 수 · D-day · **박스 분포 미니 바**(색 스택).
- 상단 [+ 단어장]. 자료 공급은 설정의 구글시트 동기화로 연결한다(수동 CSV 파일 업로드 UI는 제외).

**덱 상세(카드 목록):**
- 검색창 + 필터 칩: `전체 / 박스별 / 취약 / 졸업`.
- 카드 행: **영어 문장(말줄임) — 한글 번역(보조 텍스트)** + 박스 색 점. 문장은 한 줄에 다 안 들어가므로 1줄 말줄임 처리, 검색 비중↑.
- 스와이프 삭제, 롱프레스 다중 선택(이동/삭제).

**카드 추가·편집 폼 (문장 생산 카드):**
- 필드: **한글 문장(제시)** / **영어 문장(정답)** / 청크·문법 메모(선택) / 오디오(자동 TTS, 수동 교체 가능) / 태그.
- 핵심 청크 지정(선택): 정답 문장에서 강조할 구문을 드래그로 표시 → 학습 화면에서 색 강조.
- 저장 후 "계속 추가" 옵션(연속 입력 편의).

**자료 공급·저장:**

- 설정 → 시트 URL·대상 덱 등록 → [지금 동기화] → 가져온 문장을 공통 pool에 적재한다. CSV는 프록시와 파서 사이의 내부 데이터 형식이다.
- 생성/수정/삭제는 서버 성공 후 목록에 반영한다. 저장 실패는 오류를 표시한다. 다른 기기에서 삭제한 카드를 기존 폼 저장으로 되살리지 않는다.

### 3.6 설정

- **발음** — 정답 확인 시 자동재생 on/off, 재생 속도(보통/느리게).
- **시험 대비** — D-day 설정, D-day 주기 압축 on/off, 막판 총복습 모드.
- **알림** — 복습 리마인더 시간.
- **표시** — 다크모드, 언어.
- **콘텐츠 소스** — 시트 URL·대상 덱·자동 가져오기·[지금 동기화]. 대상 덱과 가져오기 이력은 계정별 공통 데이터다. 학습량/주기 등 공통 설정은 서버 저장 성공 후 반영한다.
- **데이터** — 내보내기(CSV)/백업, 온보딩 다시 보기(기존 계획).
- **AI 선생님** — 학습 세션의 [선생님한테 질문] 기능에 사용할 모델 선택: `Claude` / `Gemini` / `GPT`(기본 Claude). API 키는 앱이 서버에서 관리하므로 사용자가 입력할 필요 없음 (DESIGN §6).

## 4. 핵심 상태(state) 체크리스트

각 화면에서 반드시 처리할 상태:
- **빈 상태** — 카드/덱/통계 데이터 없음 → 다음 행동 유도.
- **로딩** — 가져오기/통계 계산 시 스켈레톤 또는 스피너.
- **완료** — 오늘 복습 0 → 축하 + 신규 제안.
- **에러** — 서버 읽기/저장 실패·채점 버전 충돌·시트 형식 오류 → 명확한 복구 안내. 실패를 성공으로 처리하지 않는다.
- **오프라인** — 로그인한 웹·Android 모두 학습/편집 저장은 온라인 필수. 로딩된 캐시는 열람할 수 있지만 저장 실패 시 다음 카드로 진행하지 않는다. 오프라인 변경 큐는 없다.
- **선생님 질문 패널** — 로딩 중(답변 대기), 성공(답변 표시), 에러(서버 키 미설정·네트워크 실패 → 명확한 안내 문구, 학습 흐름은 계속 진행 가능).

## 5. 마이크로카피 (한국어 톤: 담백 + 살짝 격려)

- 학습 버튼: `알았어` / `몰랐어`
- 정답 공개: `정답 확인`
- 힌트: `힌트` · 상태 표시 `힌트 1/3 · 채점 영향 없음`
- 힌트 경고(레벨 2 진입 직전): `여기서부턴 다시 볼 카드로 분류돼요`
- 힌트 초과 시 채점: `힌트를 많이 써서 다시 볼게요`
- 복습 완료: `오늘 복습 끝! 🎉`
- 빈 홈: `첫 문장 카드를 만들어 볼까요?`
- 승급 피드백: `박스 3 → 4 ↑`
- 취약 문장: `자주 막히는 문장이에요. 다시 볼까요?`
- 스트릭 위험: `오늘 학습하면 연속 7일이 이어져요.`
- 텍스트 입력 정답(관사 등 사소한 차이): `관사 차이는 괜찮아요, 정답으로 인정!`
- 텍스트 입력 오답: `아쉬워요, 다른 부분이 있어요`
- 선생님 질문 로딩: `답변 준비 중...`
- 선생님 질문 오류: `지금은 답변을 받아올 수 없어요. 잠시 후 다시 시도해 주세요.`

## 6. 구현 우선순위 (UI 기준)

- **P0(MVP)**: 홈 · 학습 세션 · 세션 요약 · 단어장/카드 CRUD · 기본 설정.
- **P1**: 통계 화면 · 온보딩 · 알림 · **텍스트 정답 입력 & 오답 diff 설명**.
- **P2**: 스와이프 제스처 · 발음(TTS) · 취약 단어 집중 세션 · 히트맵 · D-day 예측 · **선생님한테 질문(AI Q&A)**.
