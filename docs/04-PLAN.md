# 라이트너 문장 암기장 — 개발 로드맵 (WBS)

> 이 문서 = **몇 단계까지 가면 뭐가 되는지**. PRD `01-PRD.md` §6 로드맵을 실제 구현 단위(FE/BE 각각 어디까지, 어떻게 확인)로 쪼갠 것.
> MVP2는 덩어리가 너무 커서(백엔드 신설+Android 신규 제작+자동동기화가 한 번에) 중간 검증 없이 위험하므로 2a~2d로 세분화함.
> **순서 변경**: 원안은 2a→2b→2c→2d였지만, 2d(콘텐츠 자동 동기화)의 핵심 로직은 플랫폼 독립적이고 PC 웹 FE는 이미 있어서 Android(2b)를 기다릴 이유가 없다. 반면 2c(기기 간 동기화)는 Android가 있어야 의미가 있어 2b가 선행돼야 함. 그래서 **2d를 2b보다 먼저, PC 웹 범위만 진행**하고, 2d의 Android 쪽 UI(콘텐츠 소스 URL 설정 등)는 2b 완료 후에 마저 붙인다.

## 최신 상태 — 공통 pool·학습 상태 수정 (2026-10-08)

- **코드 반영 완료:** 웹·Android가 Supabase를 기준으로 pool/카드/로그/학습 설정/대상 덱/가져오기 이력을 읽는다. 캐시 union/LWW 재업로드를 제거하고 서버 읽기 성공 후 캐시를 교체한다.
- **목표·큐 수정:** 기기별 dayGoal 스냅샷 제거, 남은 큐+오늘 완료 카드 수로 목표 계산. 공통 정렬 키와 이미 소비한 하루 신규 한도를 적용한다.
- **저장 수정:** 서버 성공 후 화면 반영, pool 도입과 소비를 원자적으로 처리, 채점 진행+로그를 원자적으로 저장하고 오래된 버전은 거절. 실패 시 다음 카드로 진행하지 않는다. 로그인한 양 플랫폼은 온라인 필수다.
- **DB·인증 적용 완료:** `supabase/shared-state.sql` 적용. authenticated 역할에서 도입/채점/중복 재요청/충돌 거절을 롤백 테스트로 확인. localhost OAuth 반환 URL 허용 목록 추가.
- **검증 완료:** 웹 41개 테스트·프로덕션 빌드, Android 27개 테스트·서명 release APK 빌드 통과. 로컬 홈에서 총 363 / 목표 309 / 완료 44 및 이동 집계 32·7·5를 확인했다(당시 데이터 예시이며 제품 고정 기준은 아님).
- **배포 미완료:** Vercel 웹 재배포·새 APK 배포/설치 및 배포 후 다기기 검증은 남아 있다. 기존 클라이언트의 캐시 업로드 문제를 막으려면 양쪽 갱신이 필요하다.
- **잔여 검증:** 양방향 학습/삭제 반영, 같은 카드 동시 채점 충돌, 네트워크 단절, 실기기/배포 웹/로컬 웹 간 목표·pool 일치. 케이스는 `05-TEST-CASES-MVP1.md` §3 참고.
- **현재 한계:** 세션 화면 위치·미저장 입력과 웹 origin별 오답 다시보기 목록은 공유하지 않는다. Android의 30초 폴링·온라인 이벤트 pull도 미구현이다.

> 아래 1·2a·2b는 단계별 초기 구축 계획이며 로그인 없는 로컬 모드 설명은 당시 검증 조건이다. 현재 로그인 모드의 저장/동기화 계약은 DESIGN §3.7~3.10을 따른다. 과거 완료 기록은 당시 구현 기준으로 읽는다.

## 1. PC 웹 로컬 학습 루프 *(초기 단계, 완료)*

**목표**: 인터넷/로그인 없이 이 브라우저 안에서 라이트너 학습법 자체가 제대로 도는지 검증.

| 구분 | 내용 |
|---|---|
| FE | 홈(오늘 복습 수·박스 분포), 단어장 관리(CRUD·CSV 가져오기), 학습 화면(제시→힌트→채점), 세션 요약 |
| BE | **없음.** 모든 데이터는 브라우저 로컬 저장소(IndexedDB)에만 존재 — 다른 기기/브라우저에서 안 보임, 크롬 데이터 지우면 소실 |

**확인 체크리스트**
1. `localhost:5173` 접속 → 홈 화면 정상 표시
2. 단어장 생성 → 카드 2~3개 직접 추가 → 목록 표시
3. CSV로 문장 여러 개 한 번에 가져오기 → 결과 메시지 확인
4. [학습 시작] → 힌트 확인 → 정답 확인 → 알았어/몰랐어 채점
5. 세션 요약(오늘 몇 개 맞았는지) 표시
6. 새로고침 후에도 박스 변경 결과 유지
7. 다른 브라우저/시크릿 모드에선 데이터 없는 게 정상(로컬 저장이라 공유 안 됨 — 2c에서 해결)

---

## 2a. 클라우드 저장 연동 (PC 웹만)

**목표**: Android는 아직 없이, PC 웹 데이터가 클라우드(Supabase)에도 저장되게 한다. "동기화"보다 "백업/이어쓰기"에 가까움 — 기기가 하나뿐이라 아직 충돌은 없음.

| 구분 | 내용 |
|---|---|
| FE | 로그인 화면(구글 계정), 로그아웃 버튼 |
| BE | Supabase 프로젝트 신설(Auth + Postgres), 카드/덱/설정/학습기록 테이블(DESIGN §2.1), 로컬→서버 push·서버→로컬 pull 로직(DESIGN §3.9) |

**확인 체크리스트**
1. 구글 계정으로 로그인 → 이전 로컬 데이터가 그대로 보이는지
2. 카드 하나 학습해서 박스 변경 → 로그아웃 → 다시 로그인 → 변경 유지 확인
3. 이 컴퓨터의 크롬 데이터(IndexedDB)를 지워도, 로그인하면 클라우드에서 복원되는지
4. 현재 로그인 모드에서는 연결을 끊었을 때 저장 오류가 표시되고 다음 카드로 넘어가지 않는지(오프라인 학습 큐는 범위 밖)

---

## 2d. 콘텐츠 자동 동기화 (PC 웹만, 순서를 2b보다 앞당김)

**목표**: CSV 파일을 사람이 매번 골라 넣는 대신, 구글시트에 문장만 적어두면 앱이 자동으로 가져오게 한다. Android(2b)를 기다릴 이유가 없는 단계라 먼저 진행 — Android 쪽 콘텐츠 소스 설정 UI는 2b 완료 후 이식.

| 구분 | 내용 |
|---|---|
| FE | 설정 화면에 "콘텐츠 소스 URL" 입력란, [지금 동기화] 버튼, "자료 보충 필요" 알림 배너 |
| BE | 구글시트 공유 링크를 서버 프록시(`content-sync-proxy`, Sheets API v4)로 읽어와 새 id만 저수지로 흡수(DESIGN §3.3~3.8), 재고 부족 판정 로직, **덱 간 중복 문장 dedupe**(전체 계정 범위 dedupe 키 — 어느 덱이든 이미 카드/저수지에 있거나 importedIds에 있으면 스킵) |

**확인 체크리스트**
1. 설정에 구글시트 공유 링크(/d/{ID}/edit) 등록 + 대상 덱 선택
2. 담당자가 시트에 문장 한 줄 추가
3. 앱 재실행(또는 하루 경과) 시 그 문장이 저수지에 자동으로 나타나는지
4. [지금 동기화] 버튼으로 수동 즉시 반영도 되는지
5. 저수지 문장이 줄어들면 "보충 필요" 알림이 뜨는지
6. 서로 다른 덱을 겨냥한 시트 두 개에 같은 문장(같은 id)이 있어도 중복으로 안 쌓이는지

## 2b. Android 앱 제작

**목표**: 폰 앱 자체가 PC 웹과 동등한 기능으로 독자 완결. 이 단계에선 아직 동기화 없음(로컬 Room 저장).

| 구분 | 내용 |
|---|---|
| FE | Kotlin+Compose로 홈·단어장·학습·요약 화면 신규 제작(UXUI §3 스펙 그대로, 화면 컴포넌트는 PC 웹과 별도로 그림) + 2d의 콘텐츠 소스 설정 UI 이식 |
| BE | 없음(2c 붙이기 전, 로컬 Room 저장, 로그인 없음) |

**확인 체크리스트**
1. 갤럭시 S24(또는 emulator)에 앱 설치 → 홈 화면 표시
2. 단어장/카드 추가 — PC 웹과 동일하게 동작하는지 (수동 CSV 가져오기는 PC·모바일 둘 다 스펙 아웃, §끝의 "이전 구현·검증 기록" 참고 — 구글시트 동기화로 단일화)
3. 학습 세션(제시→힌트→채점) 폰에서 정상 동작
4. 이 단계에선 PC 웹과 데이터가 안 섞이는 게 정상(2c에서 연결)

---

## 2c. 기기 간 동기화 연결

**목표**: 2a(PC 웹+클라우드)와 2b(폰 단독 앱)를 같은 계정으로 묶어서 실제로 상태를 공유시킨다. **여기가 원래 의미하던 "기기 동기화"의 완성 지점.**

| 구분 | 내용 |
|---|---|
| FE | 로그인/복귀·학습 시작 전 자동 읽기, 웹 세션 밖 30초 갱신, 저장 대기·실패 처리(DESIGN §3.9) |
| BE | Android도 같은 Supabase에 연결, 서버 기준 캐시 교체·공통 대상 덱, 도입/채점 RPC와 채점 버전 충돌 검사(DESIGN §3.7~3.10) |

**확인 체크리스트**
1. 같은 구글 계정으로 PC 웹 + 폰 앱 로그인
2. PC에서 카드 학습(박스 승급) → 폰 앱 재실행 시 반영 확인
3. 반대로 폰에서 학습 → PC 새로고침 시 반영 확인
4. 같은 카드 버전으로 동시에 채점하면 먼저 확정된 저장만 반영되고, 오래된 저장은 오류와 함께 거절되는지
5. 양쪽 최신 읽기 후 pool·박스·목표·완료·로그 집계가 같은지, 삭제된 카드가 오래된 캐시로 되살아나지 않는지

---

## 3. 통계 · 시험 대비 · 발음 · 알림

**목표**: 진척 확인 + 시험 임박 시 전략 변경 + 발음 청취. 서로 독립적이라 순서 상관없이 개별 검증 가능.

| 구분 | 내용 |
|---|---|
| FE | 통계 화면(박스 분포·정답률 추이·스트릭 캘린더·취약 문장), D-day 설정·막판 총복습 화면, 발음 버튼, 알림 설정 |
| BE | 리뷰 로그 집계 로직, D-day 주기 압축 계산(DESIGN §1.6), 발음은 서버 없이 기기 내장 TTS(Android OS TTS / PC Web Speech API, 비용 없음) |

**확인 체크리스트**
1. 통계 화면의 박스 분포·정답률 그래프가 실제 학습 기록과 맞는지
2. 스트릭 캘린더에 학습한 날짜 표시
3. 취약 문장 목록 클릭 → 그 문장들만 집중 복습 세션 시작
4. D-day를 임박하게 설정 → 복습 주기가 짧아져 카드가 더 자주 뜨는지
5. "막판 총복습" → 이미 마스터한 카드까지 포함해서 전체 복습 시작
6. 정답 확인 화면에서 발음 버튼(또는 자동재생) 소리 확인
7. 복습 알림 시간 설정 → 그 시간에 알림 도착(폰 푸시/PC 브라우저 알림)

## 끝까지 가면(1~3 전부 완료 시)

- 갤럭시 S24와 PC(Windows/macOS) 어디서나 같은 계정으로 이어서 학습
- 구글시트에 문장만 채우면 앱이 알아서 흡수, 부족하면 알림
- 라이트너 규칙대로 오늘 복습 자동 선정, 힌트 사용량 기준 정직한 채점
- 통계로 진척 확인, 시험 임박 시 전략 자동 변경(주기 압축·막판 총복습)
- 발음 청취, 복습 알림

**끝까지 가도 안 만드는 것(Non-goals)**: 다른 사람과 계정 공유/소셜 기능, 완전 자동(무인 AI) 문장 생성, 진짜 `.xlsx` 파일 지원 — PRD §8 참고.

## 이전 구현·검증 기록 (2026-10-08 변경 전)

- **1단계 완료.** 코드 1차 작성 + 초기 버그(무한 렌더링 루프로 인한 검은 화면, 빈 입력값 무반응) 수정 + 홈 박스 시각화(계단형 채움 차트)·단어장 목록 박스/저수지 구분 표시 개선까지 반영.
- **2a 완료.** Supabase Auth(구글 로그인) + Postgres 동기화, 로그아웃 시 로컬 캐시 삭제 + 로그인 게이트 화면, 계정 전환 시 로컬 캐시 오염 방지까지 반영.
- **2d 완료(PC 웹만), 실사용 검증까지 통과.** 설정 화면(콘텐츠 소스 URL·대상 덱·자동 동기화 토글·지금 동기화 버튼), 계정 전체 범위 id dedupe(덱 간 중복 문제 포함, syncState.importedIds), 홈 화면 저수지 부족 배너.
  - 원래 계획한 "브라우저에서 직접 fetch"는 구글이 pub CSV 요청을 안티스크래핑성으로 가끔/자주 차단해 실사용 불가로 판명 → **공식 Google Sheets API(v4) 경유로 아키텍처 변경**. Supabase Edge Function(`content-sync-proxy`)이 서버측에서 Sheets API를 호출해 CSV로 변환 전달. 콘텐츠 소스 URL도 "웹에 게시" 링크 대신 평소 쓰는 공유/편집 링크로 단순화됨.
  - 실제 시트로 동기화 테스트 통과(24개 문장 흡수 확인).
  - 부수 개선: 덱 삭제 기능 신설(예전엔 없었음), 홈 박스 차트 가독성 개선(박스 번호를 카드 개수와 안 헷갈리게 x축 라벨로 분리, 차트 높이 축소).
- **2b 핵심 루프 완료, 실사용 검증까지 통과.** 개발 환경 구축(Android Studio, SDK, emulator) +
  프로젝트 골격([apps/android](../apps/android), Gradle/Kotlin 2.0/Compose/Room) + PC 웹
  `packages/core` 라이트너 스케줄러를 Kotlin으로 포팅(테스트 15개 전부 통과) + Room
  저장소(덱/카드/저수지/설정, cascade 삭제 포함) + 4개 화면(홈 박스 현황, 단어장 목록,
  덱 상세+카드 추가, 학습 세션 3단계+세션 요약) + NavHost 연결.
  - emulator에서 실제 조작으로 end-to-end 검증: 덱 생성 → 카드 추가 → 홈 통계 반영 →
    학습 시작 → 힌트/정답확인 → 채점 → 박스 승급(1→2) → 세션 요약 → 앱 강제종료 후 재시작해도
    Room에 영속 저장된 상태 유지 — 전부 확인.
  - **수동 CSV 파일 업로드는 스펙 아웃(2026-08-26)** — PC 웹·Android 둘 다 파일 업로드 UI를
    빼고, 콘텐츠 소스는 2d(구글시트 자동 동기화)로 단일화하기로 결정. PC 웹 DeckDetailPage와
    Android DeckDetailScreen에서 CSV 업로드 관련 코드 제거, "설정에서 구글시트 동기화" 안내로
    교체. CSV 파싱/dedupe 로직 자체(`lib/csv.ts`, `data/Csv.kt`)는 2d가 시트를 CSV로 변환해
    쓰는 내부 구현이라 그대로 유지.
  - **아직 안 한 것**: 실기기(갤럭시 S24) 테스트(USB 연결 문제로 보류, 2c는 emulator로 검증),
    검색/박스필터 등 PC 웹의 부가 UI, 2d(콘텐츠 자동 동기화) Android 이식.
- **2c 완료, 실사용 검증까지 통과.** PC 웹 lib/auth.ts·lib/sync.ts를 그대로 포팅:
  - `AuthRepository`(Credential Manager로 구글 ID 토큰 획득 → Supabase Auth `signInWith(IDToken)`),
    `SyncRepository`(decks/cards/new_pool/settings row 매핑 + `mergeByUpdatedAt` LWW 병합,
    PC와 완전히 같은 Supabase 프로젝트·테이블 재사용), `AppRepository`에 write-through(로컬
    저장과 동시에 클라우드 반영) + 로그인 직후 `mergeFromCloud` + 계정 전환 시 로컬 캐시
    오염 방지(PC의 LAST_SYNCED_USER_KEY와 동일 패턴, SharedPreferences로 구현) 추가.
  - 로그인 게이트 화면(PC App.tsx와 동일 원칙) + NavHost 최상단에 배치.
  - **실제 겪은 문제와 해결**: (1) `ktor-client-okhttp` 버전을 supabase-kt가 기대하는 버전과
    안 맞게 박아넣어서 `NoClassDefFoundError`로 즉시 크래시 — 버전 정렬로 해결. (2) Google
    Sign-In이 "No credentials available"로 계속 실패 — 원인이 두 겹이었음: Play 스토어 자체
    초기설정(약관 동의)이 안 끝나있었던 것, 그리고 **Android 타입 OAuth 클라이언트(패키지명 +
    디버그 키스토어 SHA-1)가 아예 없었던 것**(Web 클라이언트만 있었음 — Credential Manager
    로그인엔 이게 필수). (3) `Settings`에 `updatedAt` 필드를 추가하며 Room DB 버전을 안 올려서
    스키마 무결성 크래시 — 버전 2 + `fallbackToDestructiveMigration()`로 해결(출시 전이라
    파괴적 마이그레이션으로 충분, 정식 마이그레이션은 나중에).
  - emulator에서 실제 구글 로그인 → PC 웹에서 만든 데이터(총 48문장, 박스1=35·박스2=13)가
    그대로 동기화되는 것 확인 — 기기 간 동기화 핵심 목표 달성.
