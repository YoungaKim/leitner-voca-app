- TC-CSV-03은 "가져오기 이력"이 있어야 재현되므로, 먼저 같은 파일을 1회 가져온 뒤 다시 같은 파일로 가져오기를 실행해야 한다.
- 오류 메시지 문구는 `apps/web/src/lib/csv.ts`의 `errors` 배열 문자열과 그대로 비교한다.


## 3. 공통 pool·상태 회귀 검증 (2026-10-08)

동일 Supabase·계정, 같은 날짜, 수정 버전의 웹/Android를 전제로 한다. 기기 B의 비교는 반드시 서버 읽기 완료 후 수행한다. 실제 학습 데이터 대신 격리된 테스트 계정/덱을 사용한다.

| ID | 목적 | 단계 | 예상 결과 |
|---|---|---|---|
| TC-SYNC-01 | 로컬 로그인 반환 | localhost:5173에서 Google 로그인 | localhost:5173 유지. 배포 웹 로그인은 배포 origin 유지 |
| TC-SYNC-02 | 공통 pool·목표 | 로컬 웹/배포 웹/Android 같은 계정으로 로그인·최신 읽기 | pool id/개수, 카드 박스 분포, 오늘 목표·완료·로그 집계 일치 |
| TC-SYNC-03 | 양방향 학습 반영 | A에서 채점 저장 성공 → B 복귀/시작 전 읽기. 방향 교대 | 같은 진행/로그 반영. 목표는 각 기기에서 같은 공식으로 재계산 |
| TC-SYNC-04 | 삭제 카드 부활 방지 | B에 오래된 캐시를 남기고 A에서 삭제 → B pull·기존 편집 저장 시도 | pull에서 카드 제거, 기존 update 실패. 캐시로 서버 카드 재생성 없음 |
| TC-SYNC-05 | 동일 우선순위 정렬 | 같은 importedAt의 pool·같은 박스/복습일 카드를 다른 배열 순서로 입력 | 양 플랫폼에서 id까지 적용한 동일 큐 순서 |
| TC-SYNC-06 | 하루 신규 한도 | A에서 신규 도입·채점 후 B 최신 읽기·세션 재시작 | 잔류 박스0와 오늘 도입 후 채점 수를 newCap에서 차감, 새 한도 재발급 없음 |
| TC-SYNC-07 | 대상 덱·가져오기 이력 | A에서 시트 대상 덱 저장·가져오기 → B 읽기 | 공통 대상 덱/syncState 반영, 이미 카드화된 id는 pending 큐에 재노출되지 않음 |
| TC-SYNC-08 | 중복 신규 도입 | 같은 pool 문장을 두 기기에서 도입·같은 요청 재호출 | 서버 카드 하나와 pool 소비가 원자적으로 확정, 기존 채점 상태 초기화 없음 |
| TC-SYNC-09 | 채점 버전 충돌 | 같은 카드 버전으로 A 저장 후 B 저장 | B 오래된 저장 거절, 진행/로그 덮어쓰기 없음, 현재 문장·오류 표시 |
| TC-SYNC-10 | 채점 재요청 | 같은 log id로 RPC 두 번 실행 | 진행이 두 번 이동하거나 로그가 중복 생성되지 않음 |
| TC-SYNC-11 | 네트워크·서버 오류 | 읽기 중 오류, 채점/CRUD 중 오류 각각 주입 | 읽기 실패 시 기존 캐시 보존, 저장 실패 시 성공 UI/다음 카드 진행 없음. 웹 첫 읽기는 재시도 화면 |
| TC-SYNC-12 | 많은 기록 | review_log 1,203행 이상 준비 후 pull | 500행 페이지 반복으로 전체 기록 조회, 앞 1,000행만 집계하지 않음 |
| TC-SYNC-13 | 권한·원자성 | authenticated 역할로 본인 도입/채점, 다른 소유자 입력, 오래된 버전 시도 | 본인 요청만 성공, 실패 채점에서 카드만 변경되거나 로그만 저장되지 않음 |
| TC-SYNC-14 | 집계 의미 | 같은 카드 여러 채점 이벤트 후 홈 | 완료는 카드 수, 이동 집계는 이벤트 수. 남은 큐 내역 합계=목표-완료 |
| TC-SYNC-15 | 갱신 트리거 | 웹 비세션에서 30초/온라인복귀/탭복귀, Android 복귀·시작 수행 | 지원하는 트리거별 pull 실행. 세션 중 자동 pull로 현재 카드 변경 없음 |

### 검증 이력·남은 작업

- 웹: core+공통 sync 테스트 **41개 통과**, 프로덕션 빌드 통과. sync 테스트는 mock 기반으로 캐시 재업로드 금지·1,203행 로그 페이지 조회·읽기/쓰기 실패 전파·채점 단일 RPC 요청을 확인한다.
- Android: **27개 단위 테스트 통과**, 서명 release APK 빌드 성공. 실제 다기기 UI 동작 검증을 대체하지 않는다.
- DB: authenticated 역할의 격리 데이터 롤백 테스트로 신규 도입·채점·도입 재호출 시 진행 보존·중복 로그 방지·오래된 채점 거절 확인.
- 로컬 홈: 당시 총 363 / 목표 309 / 완료 44, 승급 32 / 강등 7 / 유지 5 확인. 이 수치는 관찰 사례이며 고정 테스트 기대값이 아니다.
- **배포 확인:** 코드 커밋 2932f80의 Vercel production 배포 성공, 운영 JS 해시와 로컬 production 빌드 일치, 신규 RPC와 남은 큐 표시 포함 확인. Android 0.1.25 서명 APK·Firebase release 0b7ds3cqkqskg 업로드 성공.
- **미완료:** 사용자 기기의 새 APK 설치 및 TC-SYNC 전체 수동 검증. 현재 열린 구버전 화면까지 자동 갱신됐다고 판정하지 않는다.
- 세션 위치·미저장 답/힌트 및 웹 origin별 다시보기 목록의 기기 간 공유는 현재 범위 밖이다.


### 에뮬레이터·로컬 웹 확인 — 2026-10-08

- 기존 Medium_Phone(Android 35) AVD 실행 후 Firebase에 배포한 0.1.25 서명 APK를 adb install -r로 설치했다.
- 기존 Google 계정으로 로그인 성공. 첫 로그인 요청은 Supabase token 요청 10초 시간 초과가 발생했으나 재시도는 성공했다. 최초 로컬 서버 읽기 오류도 이후 재동기화에서 정상 복구됐다.
- 로컬 웹과 에뮬레이터 단어장에 토익 중급 총 421 / 학습 카드 363 / 대기 pool 58, 토익 고급 0이 동일하게 표시됐다.

- 확인 범위: release APK 실행·Google 로그인·동일 계정 카드/pool·목표·최신 웹 학습의 Android 반영·재시작 로그인 유지. 전체 TC-SYNC 통과를 뜻하지 않는다.
- 배포 웹 비교 보류: 기존 배포 웹 학습 탭이 열려 있으며 새 비교 탭은 로딩에 머물렀다. IndexedDB v2→v3 캐시 버전 전환 차단이 의심되나 아직 확정하지 않았다. 진행 중 입력 보호를 위해 기존 학습 탭 새로고침 여부를 사용자에게 확인 요청했다.
- 미확인: Android→웹 채점 반영, 실제 UI 동시 채점/삭제/오프라인 저장 실패 전체 케이스. 운영 학습 기록을 테스트 채점으로 임의 변경하지 않았다.
