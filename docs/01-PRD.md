# 라이트너 문장 암기장 앱 — PRD (기획)

> **이 문서 = 왜/무엇** (제품 결정). 안정적으로 유지, 자주 안 바뀜.
> 구현 방법 → `02-DESIGN.md` · 화면 스펙 → `03-UXUI.md` · 플로우 → `flow.html`

**한 줄:** 라이트너의 "공비카드 상자"를 디지털로 재현한, **한글을 보고 영어 문장을 떠올리는(생산) 토익 대비 암기장.** 오늘 볼 것만 딱 골라 보여준다.

- 이론적 토대: 세바스티안 라이트너 『공부의 비결』 — 간격 반복 암기 상자
- 대상·목적: 오래 쉰 학습자의 **토익 문장 생산력 회복**
- 플랫폼: Android(갤럭시 S24) + PC 웹(Windows/macOS 브라우저) · 개인용(1인 사용)
- 학습 단위: **문장 카드** (한글 제시 → 영어 생산)
- 필수 조건: 같은 계정으로 폰/PC에서 동일 덱, 복습 상태, 설정, 통계를 공유해야 한다.

---

## 1. 문제 & 목표

- 오래 쉰 학습자는 단어는 알아도 **문장을 스스로 만들지 못한다.** 목표는 시험장에서 문장을 뱉는 생산 능력.
- 이미 아는 건 덜 보고, 모르는 건 자주 봐서 **시간 낭비 없이** 마감(시험일)까지 최대치.
- 자료가 끊기지 않게 **지속적으로 공급**되어야 한다(외부 생성 → 앱 자동 흡수).
- 학습을 **갤럭시 S24 폰과 PC(Windows/macOS)에서 연속적으로 이어갈 수 있어야** 한다. 이동 중엔 폰, 집/사무실에서는 PC로 이어서 복습하는 흐름을 허용한다.

## 2. 라이트너 이론 → 앱 기능

| 원리 | 앱 구현 |
|---|---|
| 능동적 인출 | 한글만 먼저 제시 → 영어 문장을 스스로 만든 뒤 정답 확인 |
| 간격 반복(망각곡선) | 박스 단계별 복습 주기 |
| 이미 아는 것 반복 회피 | 오늘 복습일이 된 카드만 큐로 생성 |
| 문장 중심 | 학습 단위 자체가 문장(예문) |
| 놀이처럼(부담 제거) | 박스 색상 시각화 · 힌트 사다리로 좌절 방지 · 연속 학습일 |

## 3. 학습 방식 (제품 핵심)

**한글 → 영어 문장 생산 + 힌트 사다리.**
앞면에 한글 문장을 주고, 학습자가 영어로 만들어 본 뒤 정답을 확인한다. 통째로 회상하기 부담스러울 때를 위해 힌트를 단계적으로 제공하되, **일정 레벨을 넘겨 힌트를 쓰면 "다시 볼 카드"로 처리**해 실력을 정직하게 반영한다. (상세 규칙 → DESIGN §1.3 / UXUI §3.3)

## 4. 콘텐츠 공급 (제품 관점)

자료는 사용자가 직접 만들거나 외부(교사·LLM)가 생성한다 → **게시된 구글 시트 1개**에 모인다 → 앱이 그 시트를 자동으로 읽어 새 문장을 흡수한다. 자료가 떨어질 것 같으면 앱이 미리 알린다. 동시에, 사용자의 학습 진행 상태(박스, 복습일, 히스토리, 설정)는 **갤럭시 S24·PC 간 자동 동기화**되어 동일한 상태를 유지한다. (파이프라인 상세 → DESIGN §3)

## 5. 주요 화면 (개요)

1. **홈/상자 대시보드** — 오늘 복습 수, 박스 분포, [학습 시작], 연속일, D-day
2. **학습** — 한글 제시 → (힌트) → 정답 확인 → 자기 채점
3. **덱/카드 관리** — CRUD, CSV 가져오기, 시트 동기화
4. **통계** — 박스 분포, 학습 곡선, 취약 문장
5. **설정** — 학습량, 복습 주기, 오답/힌트 모드, 알림, D-day, 콘텐츠 소스 URL

## 6. 로드맵

- **Phase 1 (MVP)** — 카드 CRUD + 라이트너 학습 루프(생산+힌트) + 로컬 저장 + 수동 CSV 가져오기
- **Phase 2** — 복습 알림, 통계, 발음(TTS), **게시 시트 자동 동기화 + 보충 알림**
- **Phase 3** — 기본 덱 번들, D-day/막판 총복습, .xlsx, 완전 무인 생성(Tier 2), 게임화

## 7. 확정된 결정 로그

각 항목의 구현 상세는 DESIGN 참조.

1. **학습 방식** — 한글→영어 문장 생산 + 힌트 사다리 (DESIGN §1.3)
2. **파라미터 기본값(문장 기준)** — `dailyGoal 30 / reviewCap 60 / newCap 8` (DESIGN §1.5)
3. **오답 처리** — 완화(box-2) 기본, 순수 리셋 토글 (DESIGN §1.3)
4. **세션 내 오답 재시도** — 세션 끝 1회, box/주기 미반영 (DESIGN §1.5)
5. **힌트 채점** — 레벨 1까지 무료, 레벨 2↑ 자동 오답 (DESIGN §1.3)
6. **콘텐츠 동기화** — B · 게시 구글 시트 CSV URL, 진실의 원천=시트 1개 (DESIGN §3)
7. **자료 보충** — Tier 1(버퍼+알림) + 두 저장소 모델 (DESIGN §3)
8. **기본 덱 소스** — 공개 라이선스(NGSL/NAWL/AWL) 또는 사용자·교사 생성. 상용 교재 복사 금지 (DESIGN §4)
9. **가져오기** — MVP는 CSV 전용, .xlsx는 Phase 3 (DESIGN §4)
10. **기기 호환성** — 갤럭시 S24와 PC(Windows/macOS)에서 동일 계정/환경으로 학습 상태 동기화, Supabase 사용 (DESIGN §2.1 / §3.7 / §3.9 / §4)
11. **텍스트 정답 입력** — 자기채점 버튼과 병행 제공, 관사 등 사소한 차이는 정답 처리 (DESIGN §1.3a / UXUI §3.3)
12. **AI 질문 기능("선생님한테 질문")** — 카드 컨텍스트 기반 1회성 Q&A, Claude/Gemini/GPT 중 설정에서 선택, 서버 프록시로 키 보호 (DESIGN §6 / UXUI §3.3, §3.6)
13. **박스0(신규 카드 초기 도입)** — 복습 기한 없이 언제든 노출, 채점(몰랐어/알았어) 후 무조건 박스1로 진입해 정상 라이트너 사이클 시작 (DESIGN §1.3b)

## 8. 비목표 (Non-goals, 현재 범위 밖)

- 다중 사용자 / 계정 / 소셜 공유
- 완전 무인 자동 생성(Tier 2) — 구조는 열어두되 MVP 아님
- 진짜 `.xlsx` 파싱, 클라우드 계정 동기화(OAuth)
- AI 질문 기능의 멀티턴 채팅/히스토리 저장 — 1문 1답만 지원, 스레드 UI는 범위 밖
