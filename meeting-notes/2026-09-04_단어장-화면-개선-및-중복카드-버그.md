## 진단 / 발견사항
- 구글시트는 "콘텐츠 원천"(문장 텍스트)만 담당하고, 라이트너 학습 상태(box·복습일 등)는 사용자별·기기별로 달라 시트에 못 두므로 단어장(로컬+클라우드)에 별도 저장되는 구조.
- 단어장 상세 화면이 학습 카드만 렌더링하고 저수지(대기) 문장은 목록에 안 보여서 "대기 문장 import 안 되는 것처럼" 보였음 — 실제로는 정상 흡수됨.
- 중복 카드의 근본 원인: 웹 `StudySessionPage`가 저수지 승격 시 카드 id를 랜덤 uuid로 생성 — 같은 저수지 항목이 여러 기기(웹↔웹, 웹↔안드로이드)에서 각각 승격되면 id가 달라져 동기화 병합이 하나로 못 합침. 안드로이드는 `id = pool.id`로 이미 결정적이었으나, Supabase `cards.id`가 `uuid` 컬럼이라 시트 id가 uuid 형식이 아니면 안드로이드의 클라우드 push가 실패했을 가능성.
- 진행 상태(카드) pull이 DESIGN §3.9 스펙("앱 시작/포그라운드 복귀 시 1회")과 달리 실제로는 로그인 시점 1회만 실행돼, 앱을 계속 로그인해둔 채 백그라운드↔포그라운드만 오가면 다른 기기의 변경(예: PC에서 추가한 카드)이 안 보였음.

## 결정 사항
- 카드 id는 웹·안드로이드 모두 `pool.id`(시트 id 또는 문장 내용 해시)를 그대로 쓰기로 하고, Supabase `cards.id` / `review_log.card_id` 컬럼을 `uuid → text`로 마이그레이션하기로 확정.
- 시트에 id 열이 없어도 문장 내용(한글+영어) FNV-1a 해시로 안정적 id를 생성하는 폴백을 웹·안드로이드 양쪽에 동일 알고리즘으로 적용.
- 기존에 쌓인 중복 카드는 사용자가 웹에서 수동으로 찾아 정리(콘솔 스니펫으로 조회) — 완료.
- 진행 상태 동기화: "포그라운드 복귀 시 자동 재pull"을 스펙대로 구현하기로 하고, 별도의 "진행 상태 지금 동기화" 수동 버튼은 만들지 않기로 확정(자동 트리거로 충분, 버튼 늘리면 혼란만 커짐). DESIGN 문서에 반영.
