## 진단 / 발견사항
- **reviewCap은 세션당 배치 크기일 뿐 일 상한이 아님** → 30개 풀면 뒤에 밀렸던 due가 또 올라와 "또 생겼다"처럼 보임
- **newCap이 박스0 잔류(세션 시작만 하고 미채점)를 안 세서** 새로고침마다 신규가 newCap을 넘어 불어남
- **신규 억제 기준이 "남은 due"라서** due가 목표를 넘겨도 그 due를 다 풀면 여력이 다시 열려 신규가 재유입 → "오늘 50개 봤는데 또 신규"
- 홈 숫자는 실시간 큐 잔량이라 하루 목표 기준으로 부적합
- **설정 초기화 원인**: `load()`(IndexedDB)와 `mergeFromCloud()` 경쟁 → 로컬 로드 전이면 `get().settings`가 DEFAULT라 fullSync LWW가 원격(기본값) 채택 → 로컬 덮어씀
- **중복 카드 원인**: 예전 StudySessionPage가 저수지 승격 시 카드 id를 랜덤 uuid로 생성 → 같은 저수지 항목이 웹 StrictMode 이중 실행/여러 기기에서 각각 승격되면 uuid만 다른 쌍둥이 카드. 클라우드 DB에서 18쌍 확인
- **`cards.id` uuid→text 마이그레이션이 SQL 파일만 있고 실 DB에 미적용** → 새 코드가 카드 id에 `sheet306` 같은 비-uuid를 넣으면 클라우드 저장이 조용히 실패 → 웹/모바일 데이터 발산
- 저수지 "대기" 행에 삭제 버튼 없음 (UI 공백)
