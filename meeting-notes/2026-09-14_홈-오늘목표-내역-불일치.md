# 2026-09-14 15:16 회의록 — 홈 "오늘 목표" 내역 불일치 및 localhost 로딩 문제

## 논의 주제
- 홈 화면 "오늘 목표 165개 · 완료 166개"에서 신규 개수만 보이고 박스별 숫자가 안 맞아 보임 — 신규가 목표 계산에서 빠진 게 아닌지 문의.
- 이어서 `localhost:5173`이 아무것도 안 뜨는(빈 화면) 문제 제보.

## 진단 / 발견사항
- "오늘 목표"는 하루 1회 스냅샷 고정값이라, 화면 아래 내역(`queueBreakdown`)이 실시간 잔여 큐를 보여줘 학습이 진행될수록 완료된 박스 항목이 사라지고 신규만 남아 합계가 안 맞아 보이는 것이었음(신규 자체는 원래 목표 계산에 포함돼 있었음).
- `localhost:5173` 무한 로딩("불러오는 중...")의 근본 원인: `lib/auth.ts`의 `supabase.auth.getSession()`에 타임아웃/에러 처리가 없어, 저장된 세션 토큰 문제 등으로 프라미스가 멈추면 `authReady`가 영원히 false로 남아 로딩 화면에 갇힘. 헤드리스 크롬으로 재현 확인(완전히 새 프로필에서는 정상, 기존 프로필에서는 무한 로딩).
- 위 문제를 고친 뒤에도 "일반 창"에서는 완전히 새까만 화면(로딩 텍스트조차 없음), 시크릿 창에서는 정상 — 확장 프로그램이 아니라 로컬스토리지 스키마 불일치가 원인으로 재진단: `HomePage.tsx`에서 "오늘 목표" 내역 표시 기능을 추가하며 `dayGoal` 스냅샷 스키마를 `{date,total}` → `{date,total,newCount,box}`로 바꿨는데, 기존 브라우저에 남아있던 구버전 스냅샷을 그대로 신뢰해 `dayGoal.box.map(...)` 호출 시 `box`가 `undefined`라 TypeError로 렌더링이 통째로 죽었음. 시크릿 창은 로컬스토리지가 비어 있어 문제가 드러나지 않았음.
- 브라우저 확인 과정에서 실수로 사용자의 실제(로그인된) Chrome 기본 프로필을 헤드리스로 잠깐 띄운 적이 있음(스크린샷 촬영 목적, 상호작용 없음) — 이후로는 매번 `/tmp` 아래 임시 프로필을 새로 만들어 사용하도록 전환함.

## 결정 사항
- "오늘 목표" 아래 내역은 실시간 잔여 큐 대신, 목표 총합과 같은 시점에 얼린(snapshot) 구성 내역을 보여줘서 항상 "신규 N · 박스1 M · ... " 합이 "오늘 목표 165개"와 일치하게 한다.
- 인증 세션 확인은 5초 타임아웃을 두어, 응답이 없으면 "로그인 안 됨"으로 간주하고 화면을 띄우도록 방어적으로 처리한다(이후 실제 로그인 상태면 `onAuthStateChange`가 바로잡음).
- 로컬스토리지에 저장된 구버전 스냅샷 스키마는 신뢰하지 않고 재계산하도록 유효성 검사를 추가한다(향후 스키마 변경 시 재발 방지 패턴으로 삼음).

# 2026-09-14 17:45 회의록 — 학습 완료 후 강등/승급/신규 카드 계속 복습 및 통계 정확도

## 논의 주제
- 학습 완료 화면에 강등/승급 개수를 홈에서도 보고 싶다는 요청.
- 채점에 반영되지 않는 "다시 보기(오답 재노출)" 카드를 다 안 풀고 홈으로 나가면 "오늘 목표 달성"이라며 재학습이 막히는 문제 — 복습 가능한 카드가 있으면 학습할 수 있어야 한다는 요청.
- 강등된 카드와 신규 중 틀린 카드는 맞힐 때까지 계속 복습 가능해야 한다는 요청.
- 홈에 표시된 "신규 35개 · 승급 142개 · 강등 31개 · 유지 27개"를 다 더하면 오늘 학습 완료(200개)와 안 맞는 문제, 그리고 신규→박스1 이동은 "신규"로만 집계해야 한다는 요청.

## 진단 / 발견사항
- 오답 재노출("다시 보기") 대기열이 StudySessionPage 컴포넌트의 로컬 state(`retryQueue`)에만 있어서, 다 못 끝내고 홈으로 나가면 통째로 사라짐. 홈은 `dueToday`+신규 큐만 보고 "오늘 목표"를 계산해 이미 채점 다 했으면 재노출 대기 카드가 남아 있어도 "달성"으로 표시됨.
- 승급/강등 개수도 세션 컴포넌트의 `tallyRef`에만 있어 세션을 나가면 사라짐 — 홈에서 하루 누적으로 보려면 별도 저장/재계산이 필요.
- 박스1 카드가 오답이면 더 내려갈 곳이 없어(박스1이 최저) 그대로 박스1에 머무는 경우가 있음 — 이건 승급도 강등도 아닌 "유지"라 기존 집계(승급+강등)에서 빠져 총합이 안 맞았음(142+31=173 vs 200개, 차이 27개가 유지분).
- 신규(박스0) 카드는 정답이든 오답이든 박스가 무조건 1 이상으로 올라감(박스0 밑은 없음) — 그래서 신규→박스1 이동을 "승급"으로 집계하면 신규가 승급의 부분집합이 돼, 신규를 별도 항목으로 나란히 더할 경우 총합이 어긋남(신규 35 + 승급 142 + 강등 31 + 유지 27 = 235 ≠ 200).
